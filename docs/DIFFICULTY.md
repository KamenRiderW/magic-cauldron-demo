# 步数与失败体验控制

本文记录 Demo 的数值设计：为什么要控制步数、如何把最坏情况从 127 步压到 67 步、如何用 DDA 把理性玩家的失败率降到约 3%。所有关键数字都可以用 [`tools/`](../tools/) 中的脚本或 Demo 开发者面板复现。

> 文中的 **V1.1** 指本设计方案的修订版本：相对 V1.0，修正了答案一致性、权重计算和失败概率口径；最终 Demo 在此基础上又增加了随机 T / cap 和 60 瓶初始预算。基线模型与最终版本的差异见 [`VERIFICATION.md`](VERIFICATION.md) 第 3 节。

## 1. 口径

- **操作步数** = 放到台子上并参与检测的瓶子数，即药水消耗数。
  - 提交前取回的瓶子会返还药水，不计入。
  - 已锁定的正确瓶子会自动带到下一层，不重复计数。
- **单关消耗** = 每次检测时「未锁定格数」之和。
- **理性玩家**：不会在同一格再放已被判错的颜色，其余选择随机。模拟以「理性随机玩家」为基准。
- **失败** = 当前层还需要的瓶数大于剩余药水。一旦出现立即判定失败，并从第 1 关重新开始。

## 2. 四个阶段：从 127 步到 53.6 步

| 阶段 | 规则 | 整局平均步数 | 整局最坏步数 | 主要问题 |
|---|---|---|---|---|
| ① 固定答案 | 开局随机确定答案 | 64.8 | **127**（Σn²） | 平均就超出 60 步；初始 55 瓶时失败率 87% |
| ② 保底进展 | 每次至少标对 1 格，答案从一致候选集中选 | 49.9 | 61 | 太容易：n=3、4 的关卡必定 2 次内解出，节奏单一 |
| ③ 固定难度参数 | n ≥ 4 时 T=3，cap 取 1 或 2 | 61.7 | 67 | 同一 n 的关卡体验几乎相同 |
| **④ 随机 T / cap + DDA（最终版）** | 每关在 0 ~ 最大值之间均匀随机，下一关按风险档位干预 | **53.6** | **67** | 见下文 |

最终版选择 **初始 60 瓶**：通关局平均 53.6 步，失败率约 2.9%。

## 3. 理论最坏：n²

n 个格子、n 种颜色时，理性玩家最多需要 n 次尝试。原因：每检测一次，每个未锁定格子至少排除一种颜色；n−1 次之后每格只剩一种可能。

最坏情况下要花 n² 步：每次都把排列整体平移一格，前 n−1 次全错，第 n 次才全对。

| 关卡 | n | 最多尝试 | 最坏消耗 |
|---|---|---|---|
| 1 | 3 | 3 | 9 |
| 2 / 3 | 4 | 4 | 16 |
| 4 / 5 | 5 | 5 | 25 |
| 6 | 6 | 6 | 36 |
| 合计 | — | 27 | **127** |

固定答案下，即使玩家理性，平均也要 64.8 瓶；初始 55 瓶的失败率高达 87.1%。问题不只是 127 这个理论上限，而是平均值本身就超出了 50–60 的预算。

## 4. 第一层：保底进展规则

**规则**：检测时，如果一致候选集 C 中存在能让本次至少标对 1 格的排列，答案必须从这些排列中选（常规档在保底集合内均匀随机，包括全对）。

理性玩家的排列本身就属于 C（它满足所有锁定与排除），因此这样的排列总是存在 → 理性玩家每次尝试至少标对 1 格。答案始终与全部历史反馈一致，玩家回看时不会发现矛盾。

### 4.1 穷举结论

| n | 最多尝试（原 → 新） | 最坏消耗（原 → 新） | 平均消耗（仅保底） |
|---|---|---|---|
| 3 | 3 → 2 | 9 → 5 | 4.50 |
| 4 | 4 → 2 | 16 → 7 | 6.40 |
| 5 | 5 → 3 | 25 → 12 | 9.63 |
| 6 | 6 → 4 | 36 → 18 | 13.35 |
| 合计 | 27 → 13 | **127 → 61** | **49.9** |

「最多尝试 / 最坏消耗」由记忆化搜索对 n = 3~6 全部状态穷举得出（n = 6 共 365,941 个状态），不是抽样估计。脚本见 [`tools/exact_worst_case.py`](../tools/exact_worst_case.py)。

### 4.2 直接推论

- 初始药水 ≥ 61 瓶时，理性玩家不可能失败，与运气无关。
- 平均消耗 49.9 瓶，已经落在 50–60 的预算附近；想保留一定失败压力（例如初始 55 瓶），就需要第二层 DDA 兜住运气差的玩家。
- 保底规则下，「尝试次数 = n」或「= n−1」几乎不会出现，所以不能用它来定义负体验信号，W₁ 需要改成按消耗分位判断。

### 4.3 非理性输入

如果玩家在同一格重放了已判错的颜色，他的排列不在 C 内，此时可能找不到能标对的答案，规则退化为「在 C 中尽量选标对最多的」。颜色印记和托盘上的排除提示可以让「理性玩家」假设在实际中基本成立。

## 5. 答案一致性

答案不在开局写死，而是维护一个一致候选集 C：

- 每关开始时，C 包含所有 n! 个排列（n ≤ 6，最多 720 个）。
- 每次检测时，从 C 中选一个作为「当前答案」，并据此给出标记。
- 检测后，C 收缩为「与本次标记在未锁定格上对错模式相同」的排列。

因此任何时刻都至少存在一个与全部历史吻合的答案，回看台子不会出现矛盾。这也意味着「答案延迟确定」是玩家无法察觉的：玩家看到的始终是一个自洽的系统。

## 6. 第二层：随机难度参数 T / cap

- **T（最少尝试次数）**：第 T 次检测之前不会判全对。只有在别无选择时，才允许某次一格都不对。
- **cap（单次标对上限）**：在全对之前，单次检测最多标对 cap 格。
- 两个参数都取 **0 = 不限制**，每关开局在 0 ~ 最大值之间**均匀随机**，因此仍然可能一次就猜中。

| 关卡 | n | T 最大值 | cap 最大值 | 可能的组合数 |
|---|---|---|---|---|
| 1 | 3 | 0 | 0 | 1（新手关） |
| 2、3 | 4 | 3 | 1 | 8 |
| 4、5 | 5 | 3 | 2 | 12 |
| 6 | 6 | 3 | 2 | 12 |

> 第 1 关不加难度：n=3 时若要求至少 3 次，第 1 次必须一格都不对，这一关会固定花掉 9 步，新手体验很差。

### 6.1 尝试次数与消耗分布

最终随机 T / cap、仅保底（不含 DDA）时，每种组合模拟 20,000 次后取平均：

| n | 1 次 | 2 次 | 3 次 | 4 次 | 平均步数 | 最坏步数（穷举） |
|---|---|---|---|---|---|---|
| 3 | 25% | 75% | — | — | 4.5 | 5 |
| 4 | 4.5% | 76% | 20% | — | 7.25 | 10 |
| 5 | 0.9% | 36% | 64% | — | 10.36 | 12 |
| 6 | 0.2% | 8% | 68% | 24% | 14.49 | 18 |
| **整局** | | | | | **54.2** | **67** |

> 注：n=4 在纯保底规则（T / cap 关闭）下的最坏值是 7，见 4.1；上表的 10 来自 T / cap 可能被抽到最大值时的组合，因此更高。

同一 n 的关卡会因为抽到的 T / cap 不同，呈现 1~4 次不等的节奏，避免「每关都一样」。

### 6.2 为什么不用固定参数

如果 n ≥ 4 的关卡固定 T=3、cap=1/2，n=4 的关卡几乎恒为 3 次、10 步，n=5、6 的节奏也高度一致。固定参数在数值上稳定，但体验上单调；随机参数保留了「这次可能一次就中」的惊喜，也让同一关型在不同局里有差异。

## 7. 初始药水的确定

每档 10,000 局模拟：

| 初始药水 | 仅保底·失败率 | 保底 + DDA·失败率 | DDA·通关局平均步数 |
|---|---|---|---|
| 55 | 38.0% | 17.1% | 51.1 |
| 58 | 15.2% | 7.9% | 52.9 |
| **60** | 5.9% | **3.0%** | **53.6** |
| 62 | 1.8% | 1.2% | 54.0 |
| 67 | 0% | 0% | 54.2 |

最终选择 **60 瓶**：

- 药水数本身就是步数的硬上限，通关局一定 ≤ 60 步；
- 平均步数落在目标区间中部；
- 仍保留约 3% 的失败压力，让药水有稀缺感。

## 8. 最终结果

初始 60 瓶、保底 + DDA、20,000 局：

| 指标 | 数值 |
|---|---|
| 失败率 | **2.9%**（全部发生在第 6 关） |
| 通关局平均步数 | **53.6** |
| 通关局步数分位 | P10 = 49 · P50 = 54 · P90 = 58 · 最少 37 · 最多 60 |
| 通关局落在 50–60 步 | **87.1%**（其余 12.9% 为少于 50 步的幸运局） |
| 至少被干预一关的局 | 13.5% |

低于 50 步的局来自「一次就猜中」之类的好运，这是有意保留的随机性。若要进一步收紧下限，可以把 T 的抽取改为偏向 3 的加权随机。

## 9. 失败体验分类

| 类型 | 表现 | 为什么伤害大 |
|---|---|---|
| 经济性失败 | 推理还没结束，药水先用完了 | 已投入的步数全部沉没；越靠后失败越痛，第 6 关失败意味着前 5 关白打 |
| 无进展挫败 | 连续多次一格都没标对 | 玩家得不到信息，感觉在瞎猜，推理的乐趣消失 |
| 被戏耍感 | 答案与之前的反馈矛盾，或明显被「卡」着不给过 | 破坏信任，玩家会认为系统作弊 |
| 无效操作 | 已经注定失败，却还让玩家继续摆瓶 | 浪费时间，失败被拖得更长 |
| 不可预期 | 不清楚为什么失败、还差多少 | 无法调整策略，挫败感转为放弃 |

核心判断：**失败本身不是问题，「努力推理却因运气或经济原因失败」才是负体验。** 目标不是消灭失败，而是：

1. 让理性玩家几乎不会失败；
2. 让失败发生得早、说得清楚；
3. 让系统在玩家运气差时悄悄托底。

## 10. DDA 风险模型

每关结算时计算三项风险分数。最终版按本关实际抽到的 `(n, T, cap)` 查表，只和同配置的玩家比较，避免把「抽到难配置」误判为「运气差」。

### 10.1 W₁ 相对运气

```text
q = P(同 n、同 T/cap 的玩家，本关消耗 ≥ 本关实际消耗)   // 离线表
if q <= 0.10: w1 = 1.0        // 最倒霉的 10%
elif q <= 0.25: w1 = 0.6
elif q <= 0.50: w1 = 0.2
else: w1 = 0.0

W1 = 0.5·w1[本关] + 0.3·w1[上一关] + 0.2·w1[上上关]   // 不足三关时缺项记 0
```

### 10.2 W₂ 连续失利

```text
if w1 >= 0.6: bad += 1        // 本关明显倒霉
elif w1 == 0: bad = 0         // 本关正常，清零
else: bad 不变                // w1 = 0.2：不加也不清

W2 = [0, 0.3, 0.7, 1.0][min(bad, 3)]
```

从第 1 关开始计数。

### 10.3 W₃ 经济压力

```text
E = 剩余关卡在保底规则下的期望消耗之和
M = 剩余关卡的保底最坏消耗之和（5 / 7 / 7 / 12 / 12 / 18）

if potions >= M: W3 = 0.0     // 数学上必定通关
r = (potions - E) / (M - E)
if r < 0: W3 = 1.0            // 药水低于期望，更可能失败
elif r < 0.5: W3 = 0.7
else: W3 = 0.4
```

### 10.4 综合权重与档位

```text
W = 0.35·W1 + 0.25·W2 + 0.40·W3
```

| 档位 | W | 下一关干预概率 p_match | 干预方式 |
|---|---|---|---|
| 绿 · 安全 | < 0.3 | 0% | 仅保底规则 |
| 黄 · 注意 | 0.3 ~ 0.5 | 30% | 轻度倾向匹配 |
| 橙 · 警告 | 0.5 ~ 0.7 | 60% | 中度倾向匹配 |
| 红 · 危险 | ≥ 0.7 | 90% | 重度倾向匹配 |

干预命中时，在保底集合内选择标对更多的答案：若本关有 cap 限制，把上限放宽到 `max(cap, n−3)`；cap = 0（不限）时保持不限。首次检测不直接给全对，n = 3 不启用。倾向匹配只在「选哪个排列作答案」这一层生效，消耗规则、标记规则和失败规则都不变。

### 10.5 选答案伪代码

```text
function select_target(C, guess, free, p_match, attempt, T, cap):
    groups = 按「free 位上与 guess 相同的掩码」分组
    allowed(capV):
        if attempt < T: 去掉全对组（除非只剩全对）
        去掉 0 格正确的组（除非不存在 ≥1 格的组）
        if capV > 0: 去掉标对数 > capV 且非全对的组
    pool = allowed(cap)
    if random() < p_match:
        cap2 = max(cap, n - 3) if cap > 0 else 0
        pool = allowed(cap2)
        if attempt == 1: 去掉全对
        取标对数最多的组，在其中随机
    else:
        在 pool 中均匀随机
    return 本次答案

// 检测后：C ← { x ∈ C : x 与 target 在 free 上的对错模式相同 }
```

### 10.6 失败概率

W 是风险指数，不等于失败概率。失败概率由各关消耗分布卷积精确计算：

```text
P_fail(k, potions) = P(第 k 关起的保底消耗总和 > potions)
```

开发者面板同时显示 W 与 P_fail，便于区分「风险高」和「确实快失败」。

## 12. 已知限制与后续

- 数值基于「理性随机玩家」模型；真实玩家重复犯错时不受保底上限保护。上线后应用埋点数据替换模型，重新校准分位阈值和 S₀。
- 失败全部集中在第 6 关，这是沉没成本最高的位置。可选的进一步措施：
  - 进入第 6 关前，若失败概率超过阈值，强制红档，或把第 6 关的 T / cap 抽取范围降到较低区间；
  - 失败时提供「补少量药水续玩」，替代直接从第 1 关重开；
  - 用真实玩家埋点替换理性随机模型，重新生成离线表并校准 60 瓶预算。
- 可继续探索道具、购买药水、观看广告等商业化点位，但需要重新评估失败率和步数预算。
- 当前 P_fail 仅按保底规则计算，未把 DDA 干预计入；开发者面板同时展示 W 和 P_fail，是为了区分风险指数与真实失败概率。
