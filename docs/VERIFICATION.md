# 数值验证与复现

本文说明 `tools/` 中的脚本在验证什么、怎么运行，以及它们与最终 Demo 数值之间的关系。

## 1. 工具一览

| 脚本 | 作用 | 典型耗时 |
|---|---|---|
| `exact_worst_case.py N` | 精确穷举 n=3~6 在保底规则下的最坏尝试次数与最坏消耗 | n=3/4 秒级；n=6 数分钟 |
| `sim2.py` | 单关蒙特卡洛：固定答案 / 绿 / 黄 / 橙 / 红档的消耗分布 | 约 1 分钟 |
| `run.py` | 整局蒙特卡洛：不同初始药水下的失败率、干预率、平均消耗；P_fail 卷积表 | 数分钟 |
| `walk.py` | 复现 V1.1 文档中 55 瓶示例的逐关权重计算 | 秒级 |
| `trace.py` | 搜索并校验一组符合理性约束的排列与标记序列 | 秒级 |

全部脚本使用 Python 3，仅依赖标准库。

## 2. 快速运行

```bash
cd tools
python exact_worst_case.py 3
python exact_worst_case.py 4
python sim2.py
python walk.py
python trace.py
```

### 2.1 精确穷举

```text
$ python exact_worst_case.py 3
3 (2, 5) 25
$ python exact_worst_case.py 4
4 (2, 7) 265
```

输出格式为 `n (最多尝试次数, 最坏消耗) 搜索状态数`。n=6 的搜索空间约 36.6 万个状态，需要数分钟；完整结果为：

| n | 最多尝试 | 最坏消耗 |
|---|---|---|
| 3 | 2 | 5 |
| 4 | 2 | 7 |
| 5 | 3 | 12 |
| 6 | 4 | 18 |

合计最坏 61 步，对应 [`DIFFICULTY.md`](DIFFICULTY.md) 第 4 节。

### 2.2 单关模拟

`sim2.py` 对每个 n 和每个干预档模拟 30,000 次，输出均值、最大值和消耗分布。绿色档的关键结果：

```text
3 green mean 4.50 max 5
4 green mean 6.40 max 7
5 green mean 9.62 max 12
6 green mean 13.33 max 18
```

红色档会把单关平均消耗压到约 4.95 / 6.04 / 7.16 / 8.26。

### 2.3 整局模拟

`run.py` 对初始药水 45 / 48 / 50 / 52 / 55 / 58 / 61 瓶分别模拟「固定答案 / 仅保底 / 保底 + DDA」三种模式，并输出 P_fail 卷积表。V1.1 基线的结论：

| 初始药水 | 固定答案·失败率 | 仅保底·失败率 | 保底 + DDA·失败率 |
|---|---|---|---|
| 55 | 87.1% | 8.5% | 2.9% |
| 58 | 78.0% | 1.6% | 0.4% |
| 61 | 64.5% | 0% | 0% |

### 2.4 示例校验

`walk.py` 复现 V1.1 文档中初始 55 瓶的逐关权重（L1–L5 与文档一致；脚本还会为第 6 关打印一行假设性结算，该关卡实际直接通关，不参与下一关风险计算）：

`trace.py` 则从答案和首猜出发，搜索满足「保留锁定格、不重放已排除颜色」的后续排列，并逐格核对标记数：

输出为 `n 最终答案 [(猜测, 本次消耗, 本次标对数), ...]`。

## 3. 与最终 Demo 的关系

`tools/` 中的脚本对应 **V1.1 基线模型**：

- 只有保底进展，没有随机 T / cap；
- DDA 按 n 查单关消耗分布；
- 初始药水推荐 55 瓶。

最终 Demo 在此基础上增加了两件事：

1. **随机 T / cap**：每关在 0 ~ 最大值之间抽取，离线分布表按 `(n, T, cap)` 分组；
2. **初始药水改为 60 瓶**，并把 W₁ 改为「与同 T / cap 配置的玩家比较」。

因此，最终版的 **53.6 平均步数、2.9% 失败率** 由 Demo 内置的 `DDA.simulate` 生成，而不是 `run.py` 直接输出。复现方式：

1. 打开 `magic-cauldron.html`；
2. 开发者面板选择「保底 + DDA」、初始药水 60、T / cap「随机 0~最大」；
3. 点击「按当前设置模拟 2,000 局」。

2,000 局的期望结果约为：

| 指标 | 期望值 |
|---|---|
| 失败率 | 约 3% |
| 通关局平均消耗 | 约 53.6 瓶 |
| 一次通关（按关卡） | 约 5.8% |
| ≤2 次通关（按关卡） | 约 58% |
| 至少被干预一关 | 约 13.5% |

2,000 局是小样本，结果会在 2.9%~3.2% 附近波动；离线 20,000 局的结论见 [`DIFFICULTY.md`](DIFFICULTY.md) 第 8 节。

## 4. 方法说明

### 4.1 穷举

`exact_worst_case.py` 使用记忆化搜索，以「已锁定掩码 + 当前一致候选集」为状态，同时枚举玩家的排列和答案的选择，取最坏情况：

- 保底规则下，答案只能从能让本次至少标对 1 格的候选里选；
- 玩家可以选任意与当前状态一致的排列；
- 递归到全部格子锁定，记录最多尝试次数与最坏消耗。

n=6 的状态数约 36.6 万，运行需要数分钟，但结果是精确值而非抽样估计。

### 4.2 蒙特卡洛

`sim2.py` / `run.py` 的玩家模型为「理性随机」：

- 每次从当前一致候选集 C 中均匀随机选一个排列；
- 不会在同一格重放已判错的颜色；
- 答案按保底规则（以及可选的倾向匹配）选择；
- 固定答案模式使用 honest 玩家：答案开局写死，玩家仍然理性随机。

每档单关模拟 20,000~40,000 次，整局每档 20,000 局。

### 4.3 失败概率

`run.py` 用各关单关消耗分布做卷积：

```python
def pfail(level_index, potions):
    d = {0: 1.0}
    for n in LEVELS[level_index:]:
        d = convolve(d, DIST[n])
    return sum(p for cost, p in d.items() if cost > potions)
```

得到的是「仅保底规则」下的失败概率，不含 DDA 干预。Demo 开发者面板同时显示 W 与 P_fail，前者是风险指数，后者是真实概率，两者不能互相替代。

## 5. 模型假设与局限

- **理性玩家假设**：不会在同一格重放已判错的颜色。真实玩家若重复犯错，保底上限不成立；颜色印记和托盘提示可以缓解。
- **随机模型假设**：玩家在候选集中均匀随机。会推理的玩家会更快收敛，实际消耗可能低于模拟值；但保底上限对任何理性玩家都成立。
- **DDA 概率模型**：干预命中时选择标对最多的答案，但「玩家是否能感知被托底」没有建模；这也是上线后需要埋点验证的部分。
- **离线表与线上差异**：离线表基于模拟模型生成，上线后应使用真实埋点重新校准 w1 分位阈值、p_match 和初始药水预算。
- **仅保底口径**：P_fail 表未计入 DDA 干预，因此会高估最终失败率；DDA 的实际效果以整局模拟为准。
